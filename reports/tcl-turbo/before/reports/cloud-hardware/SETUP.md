# EcoTrack cloud IR receiver and transmitter setup

The desktop and ESP32 connect to the same Supabase project through their own internet connections. The PC does not need the ESP32's local IP or the same Wi-Fi network for cloud monitoring. Initial setup and detection before registration use nearby Bluetooth.

1. Copy all of `EcoTrackCloudReceiver.ino.txt` into a new Arduino IDE sketch. This copy-paste sketch is separate from the firmware directory. Version `cloud-ir-controller-1.5-rxtx` supports Bluetooth capture metadata, decoded remote settings and IR transmission through Supabase. It captures IR in a separate task while HTTPS requests run, retains the latest full AC frame separately from noise, and excludes inherited TCL auxiliary power fields. Serial Monitor prints decoded power, setpoint, mode, fan, full packet state, TCL frame type and raw power bit. UNKNOWN frames print actual timings while IR_DEBUG_RAW is true. See reports/tcl-power/REPORT.md for the OFF verification steps.
2. Select `Heltec Wireless Stick Lite(V3)` for the HTIT-WSL_V3 board. This version compiled using ESP32 core 3.3.12, ArduinoJson 7.4.3 and IRremoteESP8266 2.9.0. Set `IR_RX_PIN` to the receiver's actual output pin; the default is GPIO 4, matching the latest Serial log. Connect a compatible receiver's VCC to 3.3V, GND to GND, and OUT to that configured pin. Connect the transmitter module S/IN to `IR_TX_PIN` (default GPIO 5), share GND, and power it at its manufacturer's rated supply with a 3.3V-compatible input. See [transmitter wiring](../ir-transmitter/WIRING.md). `IR_TX_ENABLED` defaults to true; set it false for monitoring without a transmitter. Upload in Arduino IDE. Enable USB CDC On Boot when using native USB for Serial output.
3. Fully close EcoTrack and restart it from this project with `npm start`. Sign in as an administrator.
4. Open AC Controller Devices -> Register -> Connect Nearby ESP32. Select the actual device. Pairing uses no six-digit PIN; accept the normal Windows Pair confirmation if requested. Wi-Fi provisioning and Bluetooth IR capture reads require an encrypted Bluetooth connection.
5. When live Bluetooth information confirms the ESP32 already has Wi-Fi, the wizard skips completed Steps 1 and 2. For a deleted or invalid cloud registration, enter the current Wi-Fi password once in Step 3. The receiver provisioning protocol requires that password when it receives a fresh cloud credential. For a new network, select the 2.4 GHz SSID and enter its password in Step 2, then Test Connection.
6. In Step 3, choose an existing AC profile or create a new one. Select building, floor and room, create named custom locations, or leave the whole location unassigned. Detection is optional: click Detect via Bluetooth, then press the AC remote toward the receiver during the six-second listening window. This reads a fresh capture without registering a controller. Shared/unknown protocols require manual manufacturer selection; the exact detected protocol is retained. Older sketches must be updated for this Bluetooth detection feature, or can detect after registration through Edit -> Listen for Remote Signal.
7. Click Save & Verify Controller explicitly. Pressing Enter in the password field does not register a device. The UI confirms the ESP32 cloud heartbeat, saves controller metadata and the AC binding, then marks setup complete. Failures stay visible and allow retry; Bluetooth remains available until those saves complete. Pending, unbound setup drafts are hidden from Devices and Schedules in this browser's project cache.
8. Edit can update the name, complete deployment location, optional brand and aircon type without a redundant brand-profile save. IP and SSID are hardware-reported. The editable Status field is removed; real connection indicators remain.
9. Open pages update through Supabase real-time events, with a five-second read fallback when an event is missed. Point the physical AC remote at the receiver. Supported AC protocols upload decoded remote temperature, mode, fan and power through the existing Supabase device-state record. Devices, Aircon Control and Control Schedules show those observations. Unrecognized frames show missing settings instead of a fabricated setpoint. A remote signal is an observation, not confirmation that the AC executed it.
10. Ping measures a UI -> Supabase -> ESP32 -> Supabase -> UI round trip in milliseconds. Apply Control Schedules to save the interval, wake and sleep times. Delivery remains Queued until the matching hardware receipt confirms the values. Equal wake and sleep clocks mean continuous operation; sleep controls the ESP32 rather than physical AC power.

Deep sleep disconnects Wi-Fi and Bluetooth. The receiver periodically wakes (at most 15 minutes between schedule checks) to retrieve configuration and stays awake during its operating window. Press the board's Reset/RST button for an immediate restart; Bluetooth connection prevents scheduled sleep while setup is active.

This version supports an IR receiver plus a configured transmitter. After upload, an online heartbeat with `ir_transmitter: true` enables AC controls in the UI. Registration takes its hardware role from those reported capabilities. Power, temperature, mode and fan commands use the saved supported protocol; exact detected variants are preserved. Generic or unsupported encoders produce a Failed receipt. Commands remain Queued until the matching Transmitted acknowledgement. This confirms an emission attempt, not physical AC operation. The receiver is paused during transmission to avoid treating the outgoing signal as remote monitoring. No battery readings, ambient temperature, pressure or measured AC power are generated.

Remote monitoring uses the existing latest_ir JSON. To enable command auto-deletion, run `supabase_command_retention_migration.sql` from the project root in the Supabase SQL Editor as the project owner. It keeps completed/failed/expired/superseded receipts for one hour, expires overdue queued/claimed commands even while devices are offline, and cleans up every five minutes. It leaves valid pending commands and current AC/device state intact. Command cleanup is not active until that migration is deployed. The last read-only audit found the cloud hardware functions deployed; for a new project, the existing cloud hardware migration and administrator helper are prerequisites. No live migration, cloud write, physical pairing, firmware upload or physical IR test was performed in this task. Local fixture and native Chromium form tests passed; the delivered sketch compiled for the Heltec board.

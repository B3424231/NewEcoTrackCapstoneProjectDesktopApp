# EcoTrack cloud IR receiver setup

The UI and ESP32 connect to the same Supabase project through their own internet connections. The PC does not need the ESP32 local IP. Initial Wi-Fi setup uses nearby Bluetooth.

1. Open `supabase_cloud_hardware_migration.sql` in the project root. Copy the entire file into this project's Supabase SQL Editor and run it as the project owner. It requires the existing `ecotrack_is_admin()` authentication helper. This migration was tested on isolated PostgreSQL; it has NOT been applied to the live project.
2. Copy all of `EcoTrackCloudReceiver.ino.txt` into a new Arduino IDE sketch. This is separate from the existing firmware directory. Install ESP32 core 3.3.12, ArduinoJson 7, and IRremoteESP8266 2.9.0. Select ESP32S3 Dev Module and Partition Scheme -> Huge APP (3MB No OTA). Set `IR_RX_PIN` to the real receiver output pin (default GPIO 5). Connect receiver VCC to 3.3V, GND to GND, and OUT to that pin. Upload through Arduino IDE. When using native USB, enable USB CDC On Boot to see Serial output.
3. Fully close EcoTrack and restart it from this project (`npm start`). A page reload does not load the new Electron Bluetooth handlers. Sign in as an administrator.
4. Open AC Controller Devices -> Register -> Connect Nearby ESP32. Choose the actual hardware identifier. Open Arduino Serial Monitor at 115200 baud and enter its six-digit Bluetooth pairing code when prompted. The Wi-Fi write requires encrypted, authenticated Bluetooth.
5. Enter/select the ESP32's 2.4 GHz Wi-Fi network and password. Click Test Connection and wait for its actual reply. Enter the controller details and register. Registration sends the Supabase public configuration and a device-specific credential over Bluetooth, then verifies the cloud heartbeat. Wi-Fi passwords are stored on the ESP32 and are not sent to Supabase registration or retained in browser storage. A device that was previously paired with different firmware may need its old pairing removed from Windows first.
6. Use Ping for a measured UI -> Supabase -> ESP32 -> Supabase -> UI round trip in milliseconds. This includes cloud delivery/polling and is not LAN ICMP latency. Open the registered node's Edit dialog to detect its remote brand, or use IR Studio to learn a real frame. Press the remote toward the receiver while the UI is listening. Auto-detection before cloud registration reports that registration is required.
7. Apply Control Schedules to save the interval, wake, and sleep times in Supabase. The UI reports Queued until hardware delivery. Equal wake/sleep clocks mean continuous operation. Defaults in the sketch do not enable scheduled deep sleep. The configured interval controls real connectivity history; cloud command polling remains responsive. No battery, temperature, pressure, or measured AC power is generated.

Deep sleep disconnects Wi-Fi/Bluetooth. The board periodically wakes (at most 15 minutes between schedule checks) to retrieve the latest configuration, and stays awake during its operating window. Changes made while it is asleep cannot wake it immediately. The schedule controls the ESP32, not physical AC power.

This sketch has only an IR receiver. Power, temperature, mode, and fan requests need an IR transmitter and matching transmitter-capable firmware. The UI and database reject actuation for this receiver. A future transmitted IR command is distinct from confirmed physical AC operation.

No live cloud migration, physical pairing, hardware upload, or physical IR test was performed by Codex. Browser visual verification was unavailable because the browser automation runtime failed to initialize. Error paths remain visible; no dummy IP, RSSI, latency, or capture is used as a success fallback.
